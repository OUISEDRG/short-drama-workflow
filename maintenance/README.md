## 改动的职责和流程

| 改动 | 在哪里处理 | 影响与验证 |
|---|---|---|
| 说明文档 | 负责该说明的 README/入口 | 核对导航；已登记的根 README 仍被锁 |
| 定位基础设施 | 五工具和 manifest | 基线、临时复现、全部测试、版本归档 |
| 创作规则 | 对应 Skill/reference/输出规范 | 单独授权、语义差异审查、业务测试；不能借维护改造顺手修改 |
| 单剧配置 | 获准的项目参数/台账 | 保留来源与范围，不写回公共母版 |

每次按“确认问题与范围→记录 Git 状态与原始字节备份→临时副本复现→最小修复→针对测试与全回归→基线保护对比→追加 CHANGELOG→固定版本归档→获准项目单独升级”执行。记录由谁负责、哪些文件受影响、测试名称与回退前置条件。不使用整仓 reset/clean，不覆盖已存在的报告或版本包。

```powershell
python -B tools/workflow_paths.py doctor --json
python -B -m unittest discover -s maintenance/tests -p "test_*.py" -v
python -B maintenance/maintain.py check --json
python -B maintenance/maintain.py check --baseline 'maintenance/backups/本次目录/baseline.json' --report 'maintenance/reports/新的验收.json' --json
python -B maintenance/maintain.py release --output-dir maintenance/releases --json
```

基线必须在修改前采集，包含 `JM-maintenance-baseline-v1`、采集时间、11 个保护资源的原始 SHA-256、项目参数完整业务字段、明确排除字段、文件清单及 Git 状态。该全字节保护合同用于此前基础设施维护，排除字段为空。后续如需改业务规则，应单独授权、重新定义基线合同，不能扩大排除范围隐藏变化。无 `--baseline` 记录 `not_requested`；一般健康检查和发布快照不依赖历史备份。

`check` 默认只读，发现零测试、加载错误、必需测试跳过都失败。报告只在显式 `--report` 时排他写入维护 reports。相对路径以工具定位的仓库根为准。退出码 0 为通过，2 为输入/结构错误，3 为测试或发布验收失败。没有项目的 doctor/check 都是 `lock_status=not_requested`，不能替代某部剧的内容锁和平台授权。

## 版本、稳定副本与升级

当前创作规则为 3.7.0（单镜大于0秒且不超过3秒）；基础设施发布号从根 manifest 读取，本次 1.1.1。工作流/包身份及 binding-v1、lock-v2 保持。两份 manifest 自身及当前全部28个资源继续锁原始字节。仅改两个外层目录名可恢复；固定 manifest、README、内部 Skill/reference/assets 路径和工具文件名不能任意改名。

绑定搜索为声明父范围的 0/1 层；异地默认保存公共库的普通父目录。盘符根、用户主目录或 UNC 不自动成为搜索根，需要明确的 `--search-root`，相对基准为项目目录。同盘优先保存相对范围；跨盘为明确的绝对范围，移动部分目录超出所有声明范围需要重新审查绑定。提示不能扩大范围；相同 ID 的不同副本仍报歧义。ID 不是签名，不能运行未知候选代码来认证自己。

维护目录中的文件更新不会改变运行内容锁，但根入口/运行工具更新会使绑定本维护库的旧项目出现差异。不能自动刷新锁消除差异。内容锁只能发现变化；固定旧版本必须在另一个获准位置展开归档，保存为独立版本容器，再让获准项目绑定该容器。不要扫描所有版本或跟随 latest。

```powershell
python -B tools/migrate_workflow.py plan --project '<明确获准项目>' --common '<选定版本目录>' --output '<新计划.json>'
Get-FileHash -LiteralPath '<新计划.json>' -Algorithm SHA256
python -B tools/migrate_workflow.py apply --project '<同一获准项目>' --plan '<已审阅计划.json>' --approve-plan-sha256 '<该文件摘要>'
```

同一工具支持旧物理锁迁移、v2→v2 升级、仅重绑定与 no-op。未知锁、不可映射/已删除规则、自定义 authority 来源与损坏 AGENTS 管理块阻塞；不提供 force。计划列出资源与控制字段差异、前置哈希、搜索范围和阻塞项。批准摘要仅绑定计划字节，不替代具体项目升级授权。apply 独立重新计算全部字段和 blockers；过期计划零写入。成功迁移的原锁和控制文件保存在该合成/获准项目 `_workflow_migration_backups/<计划摘要前16位>/`。无变化零写入、不生成备份；重复应用旧计划返回状态已变化，不能重复备份。

1.1.1 的历史兼容有明确边界：`4f30aee` 无 schema 锁必须是已发布 writer 的三个字段、3.5 版本、合法绝对位置提示和完整 20 项历史资源覆盖；原路径无需仍存在。相对资源路径必须精确映射，遍历、任意自定义包前缀、重复、未知或缺失资源均阻塞，新增的六项运行资源和内容变化列入审查。authority 只认可历史相对路径与正确章节组合，不丢弃字符串中的章号；有自定义根、不同父目录或不同章号时保留源文件并阻塞。1.0 默认 AGENTS 仅替换唯一的两段定位区间，支持已知 LF/CRLF 字节，保留标题、BOM 和区间外用户字节；内部修改、重复入口、坏标记或块外冲突定位指令需人工审查。

计划新增 `source_lock_format` 用于明确历史格式；旧计划须重新生成，再审核完整差异与摘要。真实历史样本和出处存于 `tests/fixtures/`，不作为生产规则或运行资源。

## 发布和恢复

release 捕获 allowlist 的运行资源、维护程序/手册/CHANGELOG、七份测试源码、明确登记的历史 fixtures 及 .gitignore，在临时冻结副本重新执行完整 check。检查期间源变动即终止。ZIP 保留原始字节与内部布局，逐项校验、解包，再运行 doctor、两个外层改名、新建合成项目、绑定、内容锁和原单段检查冒烟。测试中的 release 使用检查替身验证编排，真实完整发布在全套测试之后单独执行，避免递归。

ZIP 不包含 .git、备份、旧日志、报告、递归发布包或真实项目。测试、手册与维护程序随包保留。历史 fixtures 来自已发布 Git 字节、资源哈希和 writer 格式，位置为明确的合成提示；执行时只在临时合成项目中使用。机器可读发布记录在 ZIP 外，含实际 ZIP 摘要、逐文件摘要、运行/源码摘要、版本、测试统计和限制；无需归档自身的 ZIP 摘要。失败不留下成功标记，残留部分输出标成 `.incomplete` 或报告。归档不是 Git 发布或生产部署，不自动展开到其他真实目录。

故障时保留错误码、前置哈希与 recovery.json。项目迁移不是多文件天然原子：仅恢复本次写入、且仍匹配本次写后哈希的文件；遇到用户后续修改保留并报 residual。初始写入失败仅移除本次拥有且字节仍一致的文件，目录只在空时移除。不要递归删除已有项目。

公共维护回退也逐文件进行：先用本次验收 `changes.json` 核对当前哈希仍等于写后哈希，再验证 baseline 中备份的写前哈希，排他暂存并替换对应旧文件；新建源码先核对没有后续编辑，再移动到恢复档案，保留报告证据。任一步不匹配就停止该文件恢复。不能拿整仓备份覆盖现状。回退后再 doctor/check，并核对获准项目锁，不能把回退当作取消授权记录。

此次真实基线、验收矩阵、复现结果、改动清单留在 maintenance/backups 与 reports；报告不随发布包复制。Python 3.10 语法合同通过 AST 检查不等于 3.10 实机验证；跨父目录搬迁不等于跨物理磁盘测试；无平台操作不等于生成或成片验收。
