# 通用短剧工作流 1.1.1 更新说明

发布日期：2026-09-26。创作规则版本：3.5。基础设施版本：1.1.1。

本版补齐旧项目升级入口：自定义规则路径与章号不会再被静默改成公共默认；真实历史无 schema 物理路径锁，以及基础设施 1.0 的默认项目 AGENTS，能够经过明确审阅和摘要批准接入当前工作流。未知或冲突来源仍阻塞。

本次 GitHub 更新从基础设施 1.0 接续至 1.1.1，同时纳入此前本地完成的 1.1.0 维护框架。六个 Skill 的创作规则、三份 reference、最终输出规范、原单段检查器和项目参数母版保持原有内容，未填入单剧事实。

## 1.1.1 修复

### 自定义来源与章号保护

过去，仅凭标准文件名或路径后缀就可能把 `D:/CustomRules/ai-short-drama-director/SKILL.md` 识别为公共默认；字符串 `#9.3` 也可能被丢弃并改成默认 `7.3`。

现在只认可已发布历史模板中的完整相对路径与正确章节组合。自定义绝对根、不同父目录、不同章节、路径 fragment 与独立 section 冲突均返回审查阻塞；保留原项目文件及未知附加字段。plan 与阻塞的 apply 不写入项目。

### 真实无 schema 旧锁兼容

增加 Git `4f30aee` 初始化器真实写出的旧格式识别：`workflow_version`、`common_root`、`files`，没有 schema。严格检查 3.5 版本、字段类型、绝对位置提示、SHA-256 和 20 项必要历史资源映射；原物理目录无需仍存在。

资源路径使用精确映射。未知资源、自定义包前缀、路径遍历、重复映射或缺失必要资源继续阻塞；新增的六项运行资源与已有内容变化会列入迁移计划，供审核批准。成功后保存原锁及原控制文件字节备份，生成并核验 v2 内容锁。

### 基础设施 1.0 默认项目入口兼容

增加 Git `6d2ca1b` 已发布默认 AGENTS 的有限识别，仅替换唯一、完整的两段定位区间。保留标题、UTF-8 BOM、LF/CRLF 边界及区间外用户字节。

入口内部修改、重复旧入口、管理块损坏、新旧入口混合或块外冲突定位指令继续阻塞。新增真实 1.0 默认 AGENTS 与 26 资源 v2 锁的升级集成回归，覆盖计划、摘要批准、应用、绑定解析、内容锁及再次 no-op。

## 一并发布的 1.1.0 维护框架

- 新增 `maintenance/` 手册、CHANGELOG、具名回归、基线保护检查与冻结版本归档工具。
- 修复异地公共库改名后的绑定定位，保留 authorities 未知自定义字段，拒绝逆序/重复/缺半边管理块。
- apply 独立复算计划全部字段、阻塞项和前置哈希，再备份并写入；过期或篡改计划不能靠清空 blockers 获得通过。
- 初始化在建立项目之前预检参数、台账与单段模板，避免坏模板留下半个项目。
- 同一工具支持旧物理锁迁移、v2 内容升级、仅重绑定及无变化 no-op；不提供 force。
- release 冻结明确白名单源码，执行完整测试、ZIP 逐文件哈希及解包冒烟；历史 fixtures 随包保留，复测不依赖 Git。

GitHub 发布增加 `.gitattributes`，仅关闭历史 fixtures 的自动行尾转换，使 Windows 克隆时仍保留历史样本原始字节与哈希。其余文件继续使用仓库已有 Git 设置；已验收 ZIP 保持原字节。

## 已有项目如何升级

已有项目绑定当前维护库时，会发现入口、工具和基础设施版本的内容锁差异。请针对明确的一部项目重新生成 plan，审核资源差异、控制字段变化、原始文件前置哈希与 blockers，再按计划原字节 SHA-256 批准 apply。

计划增加了 `source_lock_format`；旧计划需要重新生成，不能直接沿用旧批准摘要。工作流和包身份、binding-v1、lock-v2 保持不变。未知格式或自定义来源须人工审查，不能自动刷新锁消除差异。

长期制作可选择固定发布包作为独立版本容器，项目明确绑定所选版本。本次发布只更新公共工作流仓库与版本附件，不自动迁移真实项目，不上传素材、不操作线上制作平台、不生成视频或消耗积分。
