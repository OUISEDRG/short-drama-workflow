## 使用方法
推荐把《交给Codex执行.md》的内容交给当前项目的Codex。也可以在本机终端按下列顺序执行。需要Python 3.10或更高版本；没有第三方依赖，不联网、不调用生成模型。

先进入解压后的升级包目录并测试：
```powershell
python -m unittest discover -s tests -v
```

预览两个已审阅目录的变更，不改正式项目：
```powershell
python apply_upgrade.py --root "D:\短剧制作" --project "被炼化后的男友悔疯了" --report-dir "预检报告"
```

阅读 `预检报告\changes.diff`，确认与本次裁决一致。全部锚点匹配后才可应用同一份计划：
```powershell
python apply_upgrade.py --root "D:\短剧制作" --project "被炼化后的男友悔疯了" --apply --plan "预检报告\plan.json"
```

应用前再次比较原文件指纹，发现并发修改即停止。实际应用先备份，再逐文件原子写入、回读校验；失败时只恢复本次仍未被其他人改动的写入。备份目录为通用目录下 `_升级记录\v3.5_apply_时间戳`。包内的初次远程备份不是这个本机应用备份。

如果旧条款锚点、模板版本、新文件位置与已审阅版本不同，脚本会停止，不猜测或覆盖。Codex应读取冲突文件，先确认差异来源；不能删除锚点检查强行应用。

## 交付内容
- `patches.json`：45个明确文本修改，覆盖11个既有文件；其他模板由payload提供。全部预览后才应用。
- `payload/`：新启动指令、排版模板、参数/台账模板、AGENTS入口和安全初始化封装。
- `apply_upgrade.py`：离线预检、备份、应用、回读和失败恢复。
- `workflow_check.py`：单段执行清单的静态合同检查。
- `init_project.py`：新项目初始化，只补缺失文件，不覆盖既有项目文件。
- `tests/`、`checks/`：回归用例及实际测试输出。
- `examples/`：仅用于说明检查格式的合成示例，不是这部剧的新提示词。
