# 剧梦短剧制作总控参考规范｜v3.4

当前执行裁决：v3.5.1（2026-09-26），单镜上限3秒，时间定义见编译器参考规范第3章；reference文件名保留v3.4。

## 0. 定位与授权边界

本规范是剧梦生产流程的“身体与手脚”，负责怎么在剧梦完成工作；它不定义剧情理解、镜头模板或视频 Prompt 语法。

- L0 当前任务永远最高：制作范围、交付、临时禁令、线上操作和积分授权以用户本次明确要求为准。
- L1 项目与资产：当前剧本、世界观、项目参数、真实素材库、已确认资产与已接受 Sequence Canon。
- L2 视频执行：读取 `../../sd25-video-prompt-compiler/SKILL.md` 及其按需参考。
- L3 导演判断：读取 `../../ai-short-drama-director/SKILL.md` 及其按需参考。
- 平台操作规则由本文件维护，并与 L0–L3 的创作和项目裁决分离。

阅读本库、生成本地 Prompt 或完成 Dry Run 均不自动授权打开线上项目、上传/删除素材、点击生成或消耗积分。执行外部动作前必须读取 `../assets/项目参数.template.json` 的项目副本或当前项目配置中的明确授权。

## 1. 保留的操作能力

以下能力完整保留：

- 剧梦网页进入、项目/集/段重锚；
- 剧本预拆解入口与完整项目状态检查；
- 剧梦真实素材库检索；
- 人物身份、角色实例和完整素材名映射；
- 顶视图站位图检索与真实 HEX 提取；
- 单独引用、一键引用、引用芯片与完整名验证；
- 模型、分辨率、时长、实时限制和计费复核；
- 生成锁、提交、队列和结果回查；
- 连续制作、任务恢复、页面异常恢复；
- 抽卡执行日志、Sequence Canon、Take 判定和单变量修正。

上述操作层不与 v3.4 导演判断竞争；不得因为更新导演大脑而删除。

## 2. 核心术语

- **集**：Episode / EP / Chapter。
- **段**：一次独立视频请求对应的剧情范围；边界由 L2 根据剧情容量、对白、顺序动作、反应与生成风险决定。
- **抽卡**：提示词就绪后，在用户已授权范围内完成剧梦配置、引用、生成提交与状态记录。
- **角色身份**：从当前项目角色表读取的正式人物名称。
- **角色实例**：当前画面中的具体视觉状态，内部键采用 `角色身份__视觉状态`。
- **剧梦完整素材名称**：当前项目素材库实际存在且引用时逐字使用的名称，须检索确认，不从模板拼造。
- **生成锁**：默认锁定；所有适用门禁和授权通过后才能解锁。
- **Sequence Canon**：仅由已接受 take 的实际可见状态组成的连续性依据。
- **规范重锚**：恢复或跨集前重新读取 L0–L3、页面真实状态、日志和已接受 Canon。

## 3. 总执行顺序

除标明可并行且无输入依赖的只读任务外，按以下阶段执行。任何阶段“不适用”都要写明事实依据，不能借此跳过仍存在的任务。

### 阶段 A｜确认任务、项目与恢复点

1. 解析 L0：剧名、起始/结束范围、交付、当前禁令、是否只做本地准备、是否允许打开平台/上传/生成/花费积分。
2. 解析 L1：剧本与对白权威版本、世界观、主语言、画幅、声音规则、素材源、项目/系列/集/段标识。
3. 若为恢复任务，先读取抽卡日志并与页面当前项目、集、段、提示词、引用、任务队列和结果状态交叉核验。
4. 页面与日志不一致时以页面真实状态和可验证证据为准；不得凭记忆重复提交。
5. 无线上操作授权时，只执行本地分析、编译与静态检查，停在可审计恢复点。

### 阶段 B｜事实预拆解

1. 先读取完整剧本和项目配置，再执行 `../../screenplay-prebreakdown-analysis/SKILL.md`。
2. 产出事实、来源、对白/VO/OS、人物知识差、空间、道具、连续性和素材候选工作包。
3. 本阶段只产出事实、声音权限、空间状态、连续性与素材候选；镜头和执行结构交给 L3 与 L2。
4. 旁白默认只转对应画面，正常现场/真实画外对白保留声音；OS不等于旁白。主语言、用户/SRT时间来源与≤3秒单镜上限写入事实工作包。
5. 预拆解完成后才进入 L3 导演分析和 L2 编译。

### 阶段 C｜剧梦真实素材检索与映射

线上检索必须已获授权。所有“存在/不存在”结论来自剧梦真实素材库，不用本地文件冒充。

#### C1. 命名体系

- 人物：`角色身份_场景或阶段_造型或状态_EP适用范围`
- 场景：`场景名称_场景形态_素材类型_EP适用范围`
- 顶视图：`场景名称_场景形态_顶视图站位图_EP编号`
- 道具：`道具名称_状态或用途_EP适用范围`

统一使用半角下划线。角色身份由项目显式映射提供；实际绑定使用剧梦真实存在、逐字一致的完整素材名称。场景、顶视图和道具执行相同规则。每个视觉状态分别建立角色实例和完整素材映射。

#### C2. 人物双层映射与角色实例

每段建立：

| 角色身份 | 角色实例 | 当前剧情状态/造型 | 剧梦完整素材名称 | 当前段使用 | 真实存在证据 |
|---|---|---|---|---|---|

选择素材必须同时满足：

- 角色身份正确；
- 当前时间阶段正确；
- 当前场景正确；
- 当前造型/服装正确；
- 当前伤势/状态正确；
- EP 适用范围正确。

同一角色同段多状态必须建立多个实例。导演分析仍理解为同一角色；Prompt Compiler、连续性和引用层分别保留实例；平台调用时转换为各自完整素材名。不能只凭角色身份就绑定该角色的全部素材。

#### C3. 顶视图

1. 进入剧梦素材库，用场景名称、场景形态、`顶视图站位图` 和 EP 共同检索。
2. 记录关键词、分类、完整素材名、缩略图核对和匹配结论。
3. 找到后提取图中真实 HEX 与文字标注，核对人物/实例、左右、前后、朝向、距离和锚点。
4. 没有匹配图时记录无匹配证据，不虚构素材或 HEX；后续使用 v3.4 空间/轴线/视线规则。
5. 顶视图是高权威起始站位参考，不是所有多人戏强制成片镜头。

### 阶段 D｜导演分析与 SD2.5 编译

1. 按 L3 完成事实锁定、开始/结束状态、导演任务、知识差、A/A+/B、Director's Read Lite（适用时）、主要视觉证据、镜头功能和 Sequence Canon。
2. 戏剧价值与生成风险分别判断：A/A+/B 不等于低/中/高风险。
3. 按 L2 判断是否拆段、时间预算、低/中/高风险、R0/R1/R2、Reference Authority、镜头连接和声音策略。
4. 每个维度只选一个最高权威参考；避免人脸、服装、姿态、道具或声音串扰。
5. 最终内容由L2第7.3节与剧梦适配Skill编译，覆盖生成约定、参考起点、镜头时间轴、末态、局部稳定性五项职责。
6. 最终展示顺序只按《资产全名版》第24节；不额外输出另一套五模块排版。
7. 不输出独立声音引用，人物附带音频保留，正常对白原文/声音不删；旁白仅画面化。所有实际人声与文字仅用本剧主语言，屏幕文字直接生成，不自动转后期。
8. 总时长源于用户要求或已确认SRT，每个实际连续镜头≤3秒；跨镜长对白只发声一次。

### 阶段 E｜配置页面与引用

每次进入或刷新页面后重新核对项目、集、段、模型、分辨率、时长模式、提示词、积分/计费和队列。旧 DOM、旧定位或上一个分镜的状态不可复用。

固定顺序：

1. 按当前页面与 L0/L1 设置模型、分辨率、时长。
2. 粘贴当前完整执行稿；只删除明确标注为非平台正文的交付说明。
3. 处理全部文字字段；不得留下未填变量或教学占位符。
4. **单独引用**所有显式人物、场景、顶视图、道具等真实素材，使用完整素材名。
5. **一键引用**人物：从角色实例映射到唯一完整素材名，逐项核对状态/造型/EP，不能按角色身份模糊绑定。
6. 返回提示词框和引用区域，重新读取实际文本、引用芯片和映射结果。
7. 填写逐名/逐实例核对表；所有应绑定项真实绑定正确、缺失阻塞为 0，才进入生成门禁。

单独引用与一键引用互不替代。普通文字、`@名称`、文件名、点击记录或“人物身份对了”都不是成功证据；真实引用芯片/卡片及完整名核对才是。

#### 一键引用超限兼容分支

当页面实时显示引用后文本超限且当前任务已授权继续处理时：

1. 保存完整母本与哈希；
2. 在完整句子/镜头边界临时分块；
3. 每块分别完成引用并保存实际已引用文本；
4. 失败块才继续细分；
5. 按原顺序回拼到同一分镜；
6. 不再次对完整稿执行会复现超限的动作；
7. 校验内容、顺序、引用芯片和哈希对应关系；
8. 同一分镜只提交一次。

不得删剧情、减少素材、用代词规避或把临时块分别生成；平台能力只按当前页面证据记录。

### 阶段 F｜生成前门禁与提交

每段生成锁默认为“锁定”。同时满足以下适用项才可解锁：

- L0 已明确授权平台生成和积分消耗；
- 页面项目/集/段/模型/时长/计费复核正确；
- L3 与 L2 分析、编译完整；
- A/A+/B、风险和 R级未混淆；
- 人物身份—角色实例—完整素材名映射齐全；
- 场景、顶视图、道具使用完整真实名称；
- 文字字段已处理；
- 单独引用完成；
- 一键引用完成或有真实、明确的不适用依据；
- 页面实际引用状态已重读；
- 逐名核对表缺失阻塞为 0；
- Reference Authority 无冲突；

- 人物引用自动附带的音频已核对且未删除，无独立声音引用模块；
- 旁白画面覆盖、正常对白保护、主语言唯一和必要文字直接生成已核对；
- 用户/SRT时间来源明确，每个实际连续镜头≤3秒，不以节拍或标签规避；
- 时间轴可行、镜间状态可接；
- 抽卡执行记录已填写；
- 当前无已提交/排队/处理中任务会导致重复扣费。

未解锁不得点击生成。用户只授权本地工作时，本阶段永久保持锁定。

### 阶段 G｜提交后状态、Take 与修正

1. 记录稳定段 ID、平台任务 ID、提示词版本/哈希、完整资产映射、提交时间、计费证据与页面状态。
2. 状态允许：计划 → 草稿通过 → 已提交 → 排队/处理中 → 生成成功/失败；平台合规判定单独记录。
3. 未知、已提交、排队或处理中先查实，不重复点击。
4. 成功后按 L2/L3 做实际证据检查：事实/身份、动作因果、空间/视线、表演/节奏、末态、声音和衔接。按实际视频切点核对每个连续镜头0<时长≤3秒；超长不通过，切点无法确定时标记待人工确认，不伪报逐帧精度。静态结构通过不能替代实际视频与音轨验收，不因此授权重生成。
5. Take 只可判为：
   - 接受：登记实际可见状态进入 Sequence Canon；
   - 后期修复：修完重验，未修不得写接受；
   - 局部编辑：保护正确层；
   - 重新采样：主体设计/参考不改；
   - 重写方案：处理过载、空间冲突、参考冲突或持续失败。
6. 修正采用单变量原则；同源问题才联动。被拒绝 take 不更新 Canon。
7. 平台明确显示“涉嫌违规内容”时，记录并停止对该 take 的规避式重试；不得删除必要引用或反复消耗积分绕过判定。后续是否重写为合规方案须服从新的明确授权。
8. 即时提示不等于最终任务状态。先按项目/集/段、任务ID、队列与历史结果核对是否已提交；未知态禁止重复点击。明确拒绝后记录原因原文，不猜触发词；仅在新授权下制作合规改稿并重新检查，不能规避平台审核。

### 阶段 H｜连续制作与停止条件

1. “制作第X集”仅授权该集；连续制作须有明确范围或已有仍有效的范围授权。没有终点不自动扩张为后续集数与无限费用。
2. 用户指定有限范围时，完成该范围的制作、复核与必要交付后停止。
3. 用户明确停止/取消时停止；其他提问或局部调整不自动取消当前连续任务。
4. 下一段若依赖上一段实际尾态，必须等 take 接受并更新 Canon；无尾态依赖的只读准备可并行。
5. 每集结束且仍有下一集时执行规范重锚；范围最后一集进入最终范围复核，不额外为了形式重锚。

## 4. 规范重锚与恢复

触发条件：

- 集末继续下一集；
- 页面刷新/重进项目；
- 上下文压缩或任务恢复；
- 模型、执行者或分镜切换；
- 日志与页面不一致；
- 无法准确说明当前集、段、步骤；
- 发现素材、引用、Prompt 或 Canon 错位。

重锚时重新确认：

- L0 当前范围、授权和禁令；
- L1 项目、剧本、对白、声音规则与完整素材映射；
- 当前页面项目/集/段、模型、时长、积分、队列和真实引用；
- 最新已接受成片的 Sequence Canon：位置、姿态、视线、持物、动作结果、场景状态、光线阶段、情绪余波、人物距离和下一段起点；
- 当前 L3 导演任务；
- 当前 L2 时间预算、风险/R级、Reference Authority 与五模块执行稿；
- 日志中最早未完成步骤。

已接受成片的实际状态在不违反更高权威时成为下一段真实起点；违反剧本事实、项目硬规则或资产身份的结果进入修正流程。

## 5. 日志合同

当前动态事实集中维护在项目《制作台账.json》，项目身份和用户裁决在《项目参数.json》；历史日志与旧Canon作为证据，不覆盖后来生效的决定。最新来源的先后靠明确时间、范围与替代关系判断，不能把旧暂停长期沿用。

每段提交前保存源稿和实际上线稿快照、各自哈希、差异、完整素材映射及人物附带音频依赖。未知队列、错误语言、超长镜头、未确认时长、对白遗漏均不能靠文字声明“通过”解除门禁。

台账分别记录：生成状态、画面检查、主语言文字检查、对白/音轨检查、单镜实际时长检查（依据实际切点；超过3秒不通过、切点不明待人工确认）、关键因果与连续性、最终Take判定。用户报告已完成与本次独立核验状态分开。默认不启用未验成片承接特例；要放宽必须有作用范围明确的新授权。只有符合当前硬规则并正式接受的结果更新Canon。

每段至少写入：

逐名核对表：

| 可编辑区标识 | 角色身份 | 角色实例 | 剧梦完整素材名称 | 当前状态/EP核对 | 引用状态与页面证据 |
|---|---|---|---|---|---|

同一角色多实例分别占行。引号内权威对白不参与名称替换，但发声者标签仍须使用正式身份且不改变原文。

## 6. 异常处理

- 页面定位失效：重读当前页面状态与 DOM，再操作；不使用旧 locator。
- 素材没找到：扩大到素材库相关分类并核对完整名；仍无则记缺口，不虚构。
- 人物身份正确但造型错：引用失败，恢复实例映射后重做。
- 一键引用静默跳过：锁定生成，重新读取真实引用状态，核对完整素材名与版本。
- 站位/轴线错误：先核对真实顶视图与最新 Canon，再只改位置、视线或对应机位。
- 普通失败/网络异常：先核对任务 ID、队列、扣费与页面状态，确认未重复提交后才按授权重试。
- 提示词问题：返回 L2 对失败变量做最小修改；同类有效尝试持续失败才重写方案。
- 日志缺失：补录可验证事实，未知写未知；不得伪造完成证据。

## 7. 完成标准

本工作流完成一次段落，不以“写完 Prompt”或“点击生成”为准，而以授权范围对应的状态为准：

- 本地任务：文件、静态检查和恢复点齐全，生成锁仍锁定；
- 生成准备：完整素材映射与页面引用证据齐全，生成锁可解锁但尚未点击；
- 已提交：平台接受且任务 ID/队列/计费可核对；
- 已接受成片：实际视听证据通过 Take 判定并更新 Sequence Canon；
- 范围交付：指定范围全部处理，成功/失败/跳过/未核验与缺片区间均明确。

本总控规范负责“怎么在剧梦完成”；导演和编译器 Skill 分别负责“这场戏为什么这样拍、如何编译成 SD2.5 可执行 Prompt、生成后如何判断”。
