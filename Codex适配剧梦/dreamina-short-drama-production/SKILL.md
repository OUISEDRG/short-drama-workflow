# 剧梦短剧制作总控

## 权威与授权

本 Skill 是 Operations Orchestrator，只负责把各层能力组织成完整生产流程。

优先级始终是：L0 当前任务 → L1 当前项目与资产 → L2 视频模型执行 → L3 导演通用原则。发现冲突时先保留更高层权威并记录受影响范围，不用模型便利性静默改写作品身份。

阅读模板、生成本地文件、打开网页、上传或删除素材、提交生成和消耗积分是不同权限。只有当前任务或项目配置明确授权的动作才能执行；没有授权时停在相应的可审计恢复点。

## 必读资源

开始完整制作、平台操作或断点恢复前：

1. 完整读取 [剧梦短剧制作总控_v3.4.md](references/剧梦短剧制作总控_v3.4.md)。
2. 复制 [项目参数.template.json](assets/项目参数.template.json) 到当前短剧项目，填写后作为该项目的 L1 配置；不要覆盖模板原件。
3. 若当前项目已有参数、日志或 Sequence Canon，读取项目实际文件，不用模板默认值覆盖。

## 模式门禁

恢复时读取项目参数、制作台账及版本锁；旧日志保留历史，不覆盖最新有效用户裁决。写本地文件不授权线上生成。

先判定当前任务停在哪一级：

- **本地分析**：只读剧本和项目文件，完成事实、导演或 Prompt 产物。
- **生成准备**：可检查剧梦页面和真实素材，完成绑定与生成前验证，但不提交。
- **平台提交**：仅在生成和积分权限均明确、所有门禁通过时提交。
- **验收与恢复**：核对任务 ID、队列、结果、实际成片和日志；未知状态先查实，不重复提交。

用户的暂停、只读、不要点击生成或限定范围要求立即收紧当前模式。

## 能力路由

按依赖关系调用，只有无输入依赖的只读工作可以并行：

1. `../screenplay-prebreakdown-analysis/SKILL.md`：建立事实、来源、VO/OS、人物知识、空间、素材候选和连续性输入。
2. `../ai-short-drama-director/SKILL.md`：形成戏剧任务、视觉证据、镜头功能与导演验收标准。
3. `../cinematic-acting-execution-library/SKILL.md`：把已选中的表演证据转为可观察、可生成的执行语言。
4. `../sd25-video-prompt-compiler/SKILL.md`：完成动态拆段、时间预算、Reference Authority 和五模块视频 Prompt。
5. `../dreamina-sd25-prompt-adapter/SKILL.md`：适配真实完整素材名、引用芯片、页面限制与生成前检查。
6. 本 Skill 按详细总控规范执行页面重锚、生成锁、提交、队列回查、Take 判定、日志和恢复。

## 不可省略的生产门禁

v3.7 G02正式进入生成准备前，必须取得v2清单与实际正文的 `quality_contract: PASS`、`current_contract_passed: true`及`sequence_scope: episode`，完成导演语义审查，并检查例外、警告和真实绑定证据。v1历史清单通过不能替代新合同。不通过仍是本地计划稿；不得标记生成准备就绪。主规则通过资源 `layout.final_prompt` 读取，不在本Skill复制另一套质量阈值。

新增本次执行合同：用户/SRT时间来源、实际每镜≤3秒、旁白画面化、正常对白原文/声音保留、主语言文字直接生成、人物附带音频保留、无独立声音引用。内容/排版职责分别由编译器第7.3节和资产全名版第24节负责。

- 当前项目、集、段、模型、时长模式、计费和队列已现场复核；
- 人物身份、角色实例和剧梦完整素材名称可逆映射；
- 场景、顶视图和道具使用真实存在且逐字一致的完整素材名；
- 单独引用、一键引用及页面实际引用状态已重新读取；
- 所有应绑定项正确，缺失阻塞为零；
- Prompt 无占位符、重复时间轴或未授权内容；
- 当前不存在可能造成重复生成或重复扣费的任务；
- 当前 L0 明确允许生成和积分消耗。

任一适用门禁失败时保持生成锁，不以“已经写完 Prompt”或“点过按钮”报告完成。

## 完成状态

使用与授权范围匹配的状态描述：本地就绪、生成准备就绪、已提交、处理中、生成失败、待验收、已接受成片或范围交付完成。只有已接受成片的实际可见状态可以更新 Sequence Canon；被拒绝、未修复或未核验的结果不得成为下一段的真实起点。

## 提交、异常与断点经验

- 用户已明确授权的连续制作在原范围内继续执行；新的“先检查”“不要生成”“暂停某集”即时收紧范围。准备任务开始时记录已有队列/视频/历史任务基线，结束时证明没有新增提交，不要求清空历史视频。
- 提交前记录提示词来源与版本、引用核验、配置、显示费用、可用余额和已有任务。余额不足保留准备结果，不反复点击；补足后先复核队列和当前授权再续作。
- 单次提交后记录回执/任务 ID 并查队列。敏感词、超时或异常提示不必然等于未入队；先确认没有延迟任务，才能重试。未知状态保持待查，不能重复扣费。
- 内容审核触发原因只能记为推测。需要改变原稿时保留原文与最小差异，在用户要求先核对时展示修改并等待确认；不能静默删对白、改责任归属、镜头顺序或资产。
- 旁白转为对应剧情证据或动作，正常对白的原文、说话人、顺序和发声保留。语言、服饰标志和画面文字策略以当前项目与最新用户裁决为准，不能把上一部剧的西语要求或后期遮挡决定带入新剧。
- 必要文字仍遵循当前工作流的直接生成合同。用户明确批准的单次后期处理只记入该项目，不改公共默认规则。
- 逐段查看实际开头、关键画面和结尾，并核对正常对白音轨；特别检查错误语言、乱码浮字、异常角标/圆点和未经要求的徽章。禁止项依当前项目确定。引用正确不代表画面正确，负面提示也不构成成片验收。
- 断点记录当前项目/集/分镜定位、稿件版本、未保存状态、资产及音频验证、任务 ID/队列、费用证据和下一步。分列准备完成、提交、出片、画面待验、音轨待验及最终接受，未验收不能报整集完成。

## 当前正式交付与阶段记录

v3.7正式本地输出必须以 `--require-profile g02_cinematic_fullname_v2` 检查本集JSON和唯一B稿。除原有质量合同外，确认current_contract_passed=true、sequence_scope=episode，并完成逐镜及逐切点语义审查。只有清单、旧profile诊断或单段PASS不能记为本集提示词完成。新合同详见layout.final_prompt及reference.shot_language，不复制第二套规则。

总控分别记录：本地Prompt静态与语义通过、平台绑定回读通过、提交回查、已生成、实际音画验收、最终接受。生成后摄影机是否按路径到达终点、转场双端是否连贯、声音身份/时点是否正确仍需实际视听证据。公共3.7升级不会自动接受旧项目锁差异；指定项目的doctor不通过时走该项目显式迁移，不刷新真实项目锁、不回退默认公共版本继续生产。
