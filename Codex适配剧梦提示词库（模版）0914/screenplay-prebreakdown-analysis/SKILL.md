# 剧本预拆解分析 Skill

## 职责边界

本 Skill 属于 L1 输入准备层。它只回答“剧本和项目已经确定了什么、哪些状态必须继承、哪些信息仍未知”，不决定戏该怎么拍。

唯一后续权威：

- 导演判断、戏剧价值、视觉证据、镜头功能与 Sequence Canon：交给 `../ai-short-drama-director/SKILL.md`。
- 动态拆段、时间预算、风险/R级、Reference Authority 与最终 Prompt：交给 `../sd25-video-prompt-compiler/SKILL.md`。
- 剧梦检索、绑定、生成门禁、日志和恢复：交回 `../dreamina-short-drama-production/SKILL.md`。

预拆解阶段只提供事实和连续性输入；段落边界、时间预算、镜头功能和执行结构由 L3 与 L2 根据当前内容决定。

## 一、先锁定来源与保护区

逐项记录：

1. 当前任务范围、集数、交付格式、临时禁令与是否授权线上操作。
2. 剧情事实权威来源、对白/VO 权威来源、版本、语言与冲突。
3. 用户指定的 SRT：只锁已确认的文字、顺序和时间；不自动证明声音资产、VO/OS 类型或平台可执行性。
4. 引号内权威对白/VO建立保护区；正式名称和素材映射不得改写其字面。
5. 影响人物、因果、对白、必要信息或空间结果的缺口标记“阻塞受影响段”；无关未知不强填。

## 二、逐集事实扫描与动态段落候选

通读完整剧本后逐集建立事件链。段落候选依据：

- 场景或时空变化；
- 关键人物出入场；
- 新信息、选择、关系或动作结果；
- 对白与顺序动作的实际容量；
- 需要等待的反应与结尾余波；
- 生成风险及 L2 是否需要拆段。

预拆解只提出候选边界和容量风险；最终“留在同一请求还是拆开”由 L2 根据对白、顺序动作、反应、空间变化和生成风险动态决定。

## 三、人物、知识与戏剧事实表

每段至少记录：

- 实际在场角色与画外角色；
- 角色知道、误解、隐瞒或刚获得的信息；
- 观众已知与本段新增证据；
- 关系/主动权的开始状态与剧本要求的结束状态；
- 权威对白、VO、OS 的说话人、对象、类型、顺序与原文；
- 关键动作、道具归属、前因与结果；
- 世界观硬规则及不得新增的事实。

角色标识使用项目确认的正式角色身份名；这不等于剧梦绑定名，且不改写引号内原文。

## 四、VO / OS 分类与权限

逐句扫描 `VO`、`V.O.`、旁白、内心独白、`OS`、`O.S.`、电话另一端及隐性叙述，记录原文、说话人、类型、时间层、信息点和声画依赖。

处理权限由 L0 当前任务与 L1 项目配置共同决定：

- 若明确要求“静默事件化”，把信息转译为有剧本依据的可见事件，不生成人声、对应口型或烧录字幕。
- 若明确要求保留 VO/OS，保留原文、身份和顺序，交给 L2 声音时间轴编译。
- 未明确时标记“待项目裁决”，不得把某一项目的静默规则升级为跨项目永久规则。
- 无论采用哪种模式，都不得删除必要信息或擅自把 VO 改成现场对白。

## 五、空间与多人状态

多人戏是否需要建立镜头，由空间理解、人物出入场和当前剧情功能决定。

记录：

- 同时实际在场的角色/群体；
- 新空间、第三人真实入场、站位重大变化或观众需重新理解空间的时点；
- 左右、前后景、距离、朝向、出入口、固定锚点；
- 视线对象、持物、动作起点/结果；
- 是否存在剧梦真实顶视图候选及其完整素材名（未检索前只写“待检索”）。

建立镜头可以承担剧情；同一空间不机械重复。第三人不得提前出现。没有顶视图不等于不能做多人戏，后续按 v3.4 轴线、视线与连续性规则处理。

## 六、角色身份—角色实例—完整素材名

三个概念必须分开：

| 概念 | 回答 | 示例 |
|---|---|---|
| 角色身份 | 剧情里是谁 | `克拉拉` |
| 角色实例 | 当前画面是哪一视觉状态 | `克拉拉__病房病号服` |
| 剧梦完整素材名称 | 平台实际引用哪一张 | `克拉拉_病房_病号服_EP09-13` |

每段建立“人物身份—素材绑定映射表”：

| 角色身份 | 角色实例 | 当前剧情状态/造型 | 剧梦完整素材名称 | 当前段使用 | 检索证据 |
|---|---|---|---|---|---|

规则：

1. 剧梦素材统一采用半角下划线命名；双下划线只用于工作流内部角色实例。
2. 角色身份由项目显式正式名称字段提供。
3. 实际绑定使用剧梦真实存在且逐字一致的完整素材名称；场景、顶视图、道具同理。
4. 同一角色同段多状态分别建立角色实例和完整素材映射。
5. 素材选择同时核对身份、时期、场景、造型/服装、伤势/状态与 EP 适用范围。
6. 剧梦素材库实际检索和页面证据共同确认素材可用性。

## 七、连续性与 Sequence Canon 输入

预拆解建立“计划状态”；已经生成的片段只有经 Take 判定为“接受”后，实际可见状态才能进入 Sequence Canon。

记录：镜/段 ID｜开头位置/姿态/视线/持物｜剧本要求改变｜计划末态｜下一段依赖。恢复或跨集重锚时另记录最近已接受成片的真实末态：人物实例、位置、姿态、视线、持物、动作结果、场景状态、光线阶段、人物距离和情绪余波。

不得让未接受 take、原 Prompt 计划或错误生成覆盖权威剧本与已锁定资产。

## 八、交给 L3/L2 的最小工作包

1. 逐集事实与段落候选表。
2. 权威对白/VO/OS 清单及声音权限。
3. 在场人物、知识差、关系起止与观众信息表。
4. 多人空间、轴线、视线、出入口与顶视图候选表。
5. 人物身份—角色实例—剧梦完整素材名称映射表。
6. 道具归属、场景状态、服装/伤势等连续性表。
7. 上一段已接受 Sequence Canon 或“尚无接受成片”。
8. 来源冲突、关键缺口和阻塞范围。

完成上述事实包后，才进入 L3 导演分析与 L2 Compiler。预拆解结果不得直接充当最终镜头设计或视频 Prompt。
